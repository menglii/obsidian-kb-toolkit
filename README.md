# 知识库工具集（kb-toolkit）

一个把「PARA + GTD + MOC 中文知识库」从零建起来、并且能一直管下去的 Obsidian 插件。

三个模块，按使用顺序排：**先有知识库 → 再管笔记 → 最后统一呈现**。

| 模块 | 干什么 | 风险 |
|---|---|---|
| **① 知识库重建** | 一键生成知识库：预览（只读）→ manifest → 执行 → 回滚，全链路带可逆日志 | 动库文件，默认**关** |
| **② 笔记自动化** | 新建空白笔记自动补 YAML 与中心链 · 改标签/属性自动归位 · 移动后同步双链 | 动库文件，默认**关** |
| **③ 更多的 Base** | 创作看板（`creation-board`）+ 内容流视图（`note-stream`） | 只读视图，默认**开** |

---

## 安装

把整个 `kb-toolkit/` 目录放进你的库：

```
<你的库>/.obsidian/plugins/kb-toolkit/
```

然后 **设置 → 第三方插件 → 已安装插件** 里打开「知识库工具集」。首次打开会自动弹一次使用向导。

> ⚠️ **首次打开新库时会看到「受限模式」提示** —— 这是 Obsidian 本体的开关，不是插件的问题。它按库存在**应用级存储**里（键 `enable-plugin-<库id>`），`.obsidian/` 目录里怎么写都关不掉。点一次「开启社区插件并重载」即可，之后不会再问。
>
> 装入本插件后，**左侧栏会出现一个图标**（书本），点它就是本插件的设置控制台。

> 想试又不想动自己的库：用仓库里的 `samples/示例库.zip`，解压成一个全新的 vault 直接用（只含空 PARA 结构 + 两个示例 `.base`，没有你的任何笔记）。

## 设置页怎么走（R20 起：R18 排版 + R19 细化 + R20 精简）

页头是标题 + 右上角版本号；下面一行是三个标签 —— **知识库 / 笔记 / Base**，标签上的小圆点就是该模块的开关状态（彩色 = 开，灰色 = 关），这一行最右端是三个按钮：**日志**（打开最近一篇操作日志）、**关于**、**帮助**（打开当前这一页的提示小窗）。
标签下面是**整行的搜索框**：输入关键字即时筛选，**命中别的标签页不会把你拽走**，而是给一条提示「当前页无命中，其他页：「笔记」N 处」—— 点它才跳过去。
每个标签页里：模块标题 + 滑动开关（外面带一圈细框）→ 一条短横 → **独立一栏「当前状态」**（一颗状态圆点 + 「已启用 / 未启用」，行尾「详情 ›」；**整栏可以点**，点开是一个悬浮窗，里面把该模块的实时状态逐条列出来）→ 几个栏目（**卡片外一个小标签 + 卡片本体，卡片里每项一行**）→ （页底不再有「帮助」栏 —— 入口在顶部标签行右端，点开仍是那个可上下滑动的小窗，本页所有说明都收在里面，一条一行）。
栏目里的按钮**一律素色**（不再有紫底 / 红底）；唯一保留警示红的是页头那条「旧插件仍在启用」横幅的「全部停用」。
「高级」折叠组默认收起，里面是低频道项（路径 / 模板与规则 / 看板显示项）。

> 看板的「卡片宽度」与「空位铺满整行」是**视图级**选项（存在 `.base` 的视图块里、跟着笔记走），所以在设置页只给指路说明 —— 到笔记里打开看板，从视图右上角 ⚙ 调。

## 首次使用

向导三步（「知识库」标签页的「辅助」栏里，「首次使用向导」可以随时重开）：

1. **目录名** — 知识库根目录（如 `01_新知识库`）、元数据目录名（如 `99_Meta`）。这两个是全插件唯一的顶层路径出口，改这里路由表与排除规则会自动重算。**知识库根目录同时是重建时新建目录的名字**（两处共用一个名字，不会再出现「库建在 A、插件去 B 找」）。
2. **模块开关** — 三个模块分别开不开。①②动库文件，建议先看过预览再开。**保存后当场生效**，不用重载插件。
3. **现场检测** — 显示根目录在不在、旧文件区在不在、顶层有多少待搬项。

## 安全底线

「动真库」这件事，本插件按这几条办：

- **重建要过三道门槛**：确认弹窗 + 勾选「坚果云已同步完成」+ manifest 校验通过。少任何一条，代码自己会拒绝执行。
- **失败即停，不自动回滚**。中断的库是「可读的半成品」，日志（`rebuild-journal.json`）里带着 `failedAt` 与错误原因。自动回滚会把失败现场也抹掉，所以交给你看过再决定。
- **回滚绝不覆盖**：只删「本轮自己建的」且 `sha256` 未变的种子文件；原位置已存在的内容一律不让路。
- **回滚不丢你重建之后写的东西（R8）**：如果新建的库里已经出现了「本轮没建过」的文件（你重建之后又写了笔记），回滚会先把它们**整体请进顶层的 `回滚保留-<时间戳>/`**（保留原本在库里的相对路径），再继续把回滚走完。收容是**移动不是删除**，一篇不丢。
- **批量删除走 `fileManager.trashFile`**，尊重 Obsidian 本体「删除文件」设置（系统回收站 / 本地 `.trash` / 永久删），不用裸删除。
- **幂等**：重复点执行不会二次破坏 —— 状态判定短路、条目级识别「已搬过」、撞名不同内容一律 blocked。
- **关掉模块就真的停手**：设置页拨掉「① 知识库重建」后，命令面板里的相关命令立刻消失、设置页的操作区**整段置灰禁用**（②③ 同理，不收起、布局零变化）；即便有残留入口调用进来，代码也一律拒绝执行并说明原因。拨开关**当场生效**，不用重载插件。
- **新建根名 = 你的库根名**：重建时的「新建目录」用的就是你配置的知识库根目录名。同名旧库会被整体归档进「旧文件」区，随后原地新建一个同名的干净库 —— 插件的路由、中心链、排除规则因此始终认得出自己的库。
- **一键补全不许静默批量改库（R8）**：先只读扫一遍列出要动的笔记 → 弹确认框 → 确认后才逐篇写，且**只加不删**。
- **`.base` 视图类型与两个内嵌视图都字节不变**：改看板/内容流的行为一律靠参数（`.base` 视图块 / 插件设置），不动内嵌代码本身。

## 再次重建（旧文件区已经有东西时）

第一次重建之后又点一次「执行」，行为和第一次**不同**（R8 起）：

| | 第一次重建 | 再次重建（旧文件区已有内容） |
|---|---|---|
| 已有的知识库目录 | 会被整体归档进「旧文件」 | **原地保留，不搬** |
| 新建的库名 | 你的库根名 | 与已有库**并列**，取 `库根名1` |
| 旧文件区下的结构 | 顶层杂物直接搬进 `旧文件/<原名>` | 新建两个子文件夹分代存放 |

两个分代子文件夹（**第一次重建不会创建**，因为那时没有"旧文件"）：

```
旧文件/
├── 先前已有-20260917-1130/    ← 再次创建之前就躺在旧文件区里的东西
└── 本次移入-20260917-1130/    ← 这次搬进来的顶层杂物
```

好处是「上一轮归档」和「本轮移入」不再混在一起，也不会因为同名而互相挡路（撞名判据是「目标位此刻存不存在」，分代之后正常路径压根产不出撞名）。

## 创建补全会写什么（R7 模板系统 · R8 模板库文件化）

新建一篇**空白**笔记时（② 开着），插件会按模板补上前言与尾部双链。补什么由你定的模板决定：

| 内置模板 | 适合 |
|---|---|
| PARA 待整理（默认） | 八字段前言 + 关联笔记；不确定用哪套就用它 |
| 轻量收件 | 只要 tags 与日期，正文留白 —— 速记 |
| 项目笔记 | 状态直接置为「进行中」，带目标 / 下一步两栏 |
| 资料收集 | 带「来源 / 摘要 / 我的想法」三段 |

**模板就是文件**（R8 起）：一套模板 = 模板库目录下的一个 `.md`

```
<库根>/<元数据目录>/02_模板库/Templater/*.md
```

在设置页里改、或者在 Obsidian 里直接打开那个 `.md` 改 —— **都是同一份**。设置页的「内置模板写入模板库」会把四套内置落盘成文件；「另存为新模板」「从笔记提取…」也都直接落在这个目录里；「删除此模板」走回收站（不硬删）。

> ⚠️ **那个目录同时也是 Templater 的模板目录**，两种模板能混着放，但插件对它们区别对待：
> - **普通模板**（只有 `{{占位符}}`）→ 直接渲染落盘。
> - **Templater 模板**（正文含 `<% %>` / `<%* %>`）→ 先把模板交给 Templater 求值，拿到成品再写。
>   求不到值（Templater 没装 / 报错）就**跳过不动手**并提示你 —— 宁可不补，也不会把模板语法写进笔记。
> - **目录已被 Templater 的「目录模板」接管**（Templater 设置里配了该目录，且开着「新建文件触发」）→
>   **正文**整个让给 Templater，本插件不插手（避免两边互相覆盖）；但**属性照补** ——
>   只往前言里加上「文件位置」这一个键（**只加不覆盖**，已有就跳过；值**留空**）。
>   这样新笔记一落地，属性面板里就有这一行，点它选一个目录，笔记就会自动搬过去，
>   并同步更新 YAML 与尾部双链。留空是有意的：路由判定是「文件位置非空则以它为准，为空才按标签归位」，
>   填成当前目录反而会把「按标签归位」这条路掐死。关掉「写回笔记」开关则完全不碰前言。

**套用规则**：可以指定「哪个文件夹下 / 哪个标签下的新笔记用哪套模板」。命中优先级：

```
标签规则  →  文件夹规则（最长前缀优先）  →  「当前模板」兜底
```

都不中时如实按「当前模板」补，不会谎报命中了某条规则。

模板里只有六个占位符会被替换，其余原样落笔：

```
{{title}} 笔记名    {{date}} 创建日期    {{folder}} 所在目录（相对库根）
{{center}} 所属中心页   {{moc}} MOC 知识地图   {{kb}} 库根名
```

写错的占位符（比如 `{{标题}}`）**不会被清空**，会原样留在笔记里 —— 看得见才好修。

补全只对**空白新文件**生效：已经写了字的不会被覆盖（粘贴、Templater 已注入的场景都安全）。

**R8 提速**：空白新笔记的补全不再固定干等 0.8 秒 —— 起步只等 180ms，这期间若 Templater 又落了笔（同一条路径再来事件）就自动续期，累计封顶 800ms。多数情况下你新建完切过去，前言与双链已经在了。

## 一键补全（② 组 / 命令面板）

给**已经有内容**的笔记批量补齐（老库迁移、导入的笔记最常用）：

1. 设置页「笔记」标签页的「批量操作」栏点「开始扫描」（或命令面板 `笔记自动化：一键补全`）；
2. 插件**只读**扫一遍整个知识库，列出要动的笔记与要补什么；
3. 弹确认框 → 你点「确认补全」才真的写；
4. 补完在 `<库根>/<元数据目录>/05_操作日志/` 留一篇报告。

补法**只加不删**：

- 完全空的笔记 → 套整套模板；
- 有正文的 → 只在**缺的位置**补：开头补 YAML、结尾补「关联笔记」双链。原有正文一个字符不动。

已经完整的笔记、模板库目录里的 `.md`、排除目录（含旧知识库）一律跳过。补过之后再扫是 0 篇 —— 幂等，不会重复写。

## 标签-目录映射表（② 组「批量操作」栏 →「查看 / 编辑」）

点这个按钮会弹出当前的 12 条路由，每条列出**可识别写法**（标签或「文件位置」属性的值），并顺手体检：

- **前缀不是当前库根的** —— 多半是改过库根名又手改过路由表，这些路由会指向一个不存在的目录；
- **目标目录在当前库里不存在的** —— 可能只是还没重建出目录，也可能是路由真的过时了。

## 操作日志（会落在你自己的库里）

预览 / 执行 / 回滚各会写一篇**可读的 Markdown 报告**到：

```
<库根>/<元数据目录>/05_操作日志/2026-09-17 0930 知识库重建·预览.md
```

里面有概览表（状态 / 新建根 / 旧文件区 / manifest 自校验）、搬运清单（源 → 目标 / 类型 / 字节 / sha256）、目录与种子清单、冲突与排除、失败时停在哪一步、以及下一步该点什么。这类报告是**笔记实体**，能被 Base 检索、能被双链引用，尾部双链回 `MOC_知识地图`。

执行报告写在新建根里时会被登记为「可逆」—— 回滚会把它一起收走（否则新建根删不干净）；写在别处的中断报告属于**留档**，回滚不抹掉。

## 创作看板怎么设置（R22 悬浮小窗 · R23 属性开关 · R24 板块级右键小窗）

看板上的设置分三层，作用域从大到小，**各写各的**、互不打架：

| 入口 | 管什么 | 怎么开 |
| --- | --- | --- |
| 视图标题（Bases 自带的视图选项） | 显示类：显示属性 / 显正文 / 正文字数上限（3 项） | 点视图标题 |
| 顶栏齿轮「板块」 | **整个看板**：卡片宽度拉杆 + 自动；看板行为（允许重复 / 显示收容所 / 显正文 / 属性默认展开 / 只读）；板块清单增删；高级（YAML / 双链 / 拖动搬文件 / 配置搬运） | 点看板右上角齿轮 → 居中悬浮小窗（✕ / 点窗外 / Esc 收起） |
| **右键板块标题**（R24） | **只对这一个板块**：刷新 · 通用设置（属性展开 / 内容展开 / 重置设置 / 显示帮助）· 笔记内容（显示 YAML / 显示双链）· 文件操作（拖动搬文件 / 文件隐藏显示 / 查看隐藏的文件） | 鼠标移到板块标题上点右键，**在鼠标处**弹出小窗 |

- 板块级的四项（属性展开 / 内容展开 / 显示 YAML / 显示双链）都是**三态**：`继承`（跟随上面的视图设置）/ `开` / `关`。选了开或关就**只改这一块**，别的板块不受影响。
- 「重置设置」只清**这一个板块**的覆盖（回到「继承」），不动视图级设置；没有覆盖时它是灰的。
- **双击板块名**可以就地改名；**拖动板块标题**可以给板块排序（落在目标左半边 = 插到前面，右半边 = 插到后面）。
- 「文件操作」那一组是**整个看板共用**的（组头写着「整个看板」），所以用的是打勾项而不是三态 —— 免得让人以为能按板块设。
- 「文件隐藏显示」开着时，可以在**卡片上右键 → 隐藏这篇**把某篇收起来。默认它**完全不渲染**，板块头显示「已隐藏 N」；想看就把「查看隐藏的文件」勾上，它会带虚线淡出回来，再右键「取消隐藏」即可。
- 板块之间有一条细分隔线（相邻板块才画，子分组不受影响）。

## 配置与存储

- 设置存 `data.json`（带 `schemaVersion` 迁移链）。
- 重建的运行时文件写在**插件目录**，不碰笔记：`rebuild-preview.json`（计划）、`rebuild-manifest.json`（执行依据）、`rebuild-journal.json`（可逆日志）。
- 三种操作的可读报告写在**库内** `<库根>/<元目录>/05_操作日志/`（见上节）。
- 创造看板的板块配置存在 `.base` 的**视图块**里（Obsidian 原生机制，随笔记一起同步）。

## 开发与测试

无打包器依赖，`src/*.js` 按文件名序拼接 + `vendor/` 字节级内嵌：

```bash
NODE="<node>"; export NODE_PATH="<node_modules>"
cd .obsidian/plugins/kb-toolkit
"$NODE" scripts/build.js          # → main.js + styles.css
"$NODE" tests/run_all.js 3        # 全套 22 个套件 × 3 轮
```

测试跑的是**构建产物** `main.js`，改过 `src/` 必须先 build。全套断言用 stub obsidian（覆 `Module._load`）+ jsdom，**全离线**，期望值从真实文件/配置动态推算。当前 **2050 断言 / 每轮 0 失败**（`run_all.js 3` → 6150）。其中 `run_r26.js`（85 条）是 R26 等高留白 / 板块级卡片高度 / 勾选框直点 / 长按菜单 / 单击改名的专属套件，`run_r25.js`（122 条）是 R25 板块级文件宽度 + 右键菜单三件套的专属套件，`run_r20b.js`（248 条）是**看板真 DOM 冒烟** —— 源码级正则抓不到「改完当场抛异常」，它把内嵌看板真造出来、真点面板与编辑行。

重建的执行/回滚还必须过**真文件沙盒**（真 fs 的 `renameSync`/`rmSync`），以及把真库整棵拷进工作区再演一遍：

```bash
"$NODE" ../../../.workbuddy/tmp/sandbox_r4b/run.js     # 229 断言 / 失败 0
python ../../../.workbuddy/tmp/preplay_lab.py          # 真库副本 247 断言 / 失败 0
```

jsdom 桩的 `delete` 不看 `force`、`rename` 不校验父目录，会盖住「目录非空删不掉」「收容目标父目录不存在」这类错 —— 只有真文件沙盒抓得到。

## 版本库与提交

仓库：**https://github.com/menglii/obsidian-kb-toolkit**（私有）。仓库根 = 本插件目录 —— **不要**在 vault 根 `git init`。

一次改动的最小提交路径：

```bash
"$NODE" scripts/build.js          # 1) 先重建，产物必须与 src/ 同步
"$NODE" tests/run_all.js 3        # 2) 全绿再提交
git add -A                        # 3) main.js / styles.css 一起进（它们故意纳入版本库）
git commit -m "..." && git push
```

两条本机约束：

- **远端只走 SSH**（`git@github.com:...`）：本机 HTTPS 走代理会被 502，`gh` CLI 也没装。
- 本机全局 `core.autocrlf=true` → `.gitattributes` 里 `* text=auto eol=lf` 压住它，否则签出时全部源码被静默改写成 CRLF。新增由脚本以 CRLF 生成的文件时，记得补一条 `-text`。

> 跑完全套测试后 `samples/_sample_manifest.json` 的 `generated` 时间戳会被刷新（`run_r5` 会重算示例库）。
> 内容其余部分是确定的 —— 提交前 `git checkout -- samples/_sample_manifest.json` 忽略这次 churn 即可。

## FAQ

**Q：会动我的笔记吗？**
A：只有①②会，且都默认关闭。③是只读视图。重建走「预览 → 确认 → 执行 → 可回滚」，预览阶段不改动任何已有笔记（只写一篇操作日志报告）。

**Q：装好插件后左栏没有图标 / 命令面板里没有命令？**
A：先确认设置里「① 知识库重建」是打开的 —— 模块关着时命令**根本不会注册**，这是有意为之。图标（书本）点了会直接打开本插件的控制台。

**Q：我自己的目录名不是 `01_新知识库` 怎么办？**
A：在设置页「知识库路径」里改，或走向导。路由表与排除规则会跟着重算，代码里没有写死的顶层路径。

**Q：改用标签自动搬家，会不会把我文件搬乱？**
A：做的是**确认式**（预览 → 确认 → 执行），且撞名一律不覆盖。属性里写「位置锁定: true」的文件永不被搬。

**Q：重建之后想反悔？**
A：「回滚」按钮按日志逆序撤销：搬回去、删掉本轮建的目录与种子。原位置已有内容的一律跳过并报告。**重建之后你自己在新库里写的笔记不会被删** —— 回滚会先把它们请进 `回滚保留-<时间戳>/`，再继续把回滚走完。

**Q：设置页输入框打不进去字 / 敲一个字就跳走？**
A：R8 起已修（根因是 Obsidian 的输入框每按一个键都回调，旧代码一回调就重画整页、把焦点丢了）。现在**按键只记草稿，失焦或回车才落库**。若还遇到，请说清是哪个输入框。

**Q：创作看板为什么默认显示整个库了？**
A：R8 起默认「排除目录」为空 = 不排除任何目录 = 展示整个笔记库。想挡掉某个目录（比如元目录）就在设置页「创作看板 · 排除目录」里按**目录段**写，例如 `99_Meta`。

**Q：一键补全会改坏我的笔记吗？**
A：不会。它**只加不删** —— 空笔记套模板，有正文的只在开头补 YAML、结尾补双链，原有正文一个字符不动；而且必须先过确认框。跑完有不放心的地方，去 `<库根>/<元数据目录>/05_操作日志/` 看那篇报告。

**Q：向导里改了设置，为什么不用重载？**
A：R7 起保存即生效 —— 模块当场启停、在跑的模块按新库根就地重配、正开着的设置页当场重画。Notice 会明确写「已保存并已生效」。

**Q：重建之后新建的笔记没被补上 YAML？**
A：先看两件事：①「② 笔记自动化」开着吗（关着时创建补全根本不注册）；② 设置页「知识库根目录」跟重建出来的目录名是不是同一个（R7 起它们必然是同一个）。若还不行，点「查看路由条数」看路由前缀是否指向当前库根。
